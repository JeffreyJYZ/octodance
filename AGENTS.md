# octodance

Minimal Next.js App Router site.

Published: <https://github.com/JeffreyJYZ/octodance> (public; `main` tracks `origin/main`).

## Stack

- Next `16.3.8` (App Router, Turbopack) + React `19.3.0`
- TypeScript `7.0.2` (native port), `strict`, path alias `@/*` → `./src/*`
- Tailwind CSS `4.3.3` via `@tailwindcss/postcss` (`src/app/globals.css` = `@import "tailwindcss";`)
- Biome `2.5.15` — formatter + linter (tabs, width 4)

## Commands

- Package manager: **bun**.
- `bun dev` · `bun run build` · `bun check` (= `biome check --write`)

## Gotchas

- **Next rewrites `tsconfig.json` on the first build** — sets `jsx` to `react-jsx` (from `preserve`), `allowJs` to `true`, and expands `lib`. It reformats to 2-space. Run `bun run check` (or `biome format --write`) afterwards to restore tabs; the next build then leaves it alone.
- Biome 2.5 deprecated `linter.rules.recommended` → use `"rules": { "preset": "recommended" }`.
- Biome does not read `.gitignore`; `.next`/`node_modules` are excluded explicitly in `biome.json` (`files.includes`).
- **Fonts**: definitions in `src/ui/fonts.ts` (`next/font/local`), file assets in `public/fonts/`; consumed in `src/app/layout.tsx` via `@/ui/fonts`.
  - `Satoshi-Variable.woff2` + `Satoshi-VariableItalic.woff2` → `--font-satoshi` (weight `300 900`) → Tailwind `--font-sans` (default body font).
  - `CODE-Light.otf` (300) + `CODE-Bold.otf` (700) → `--font-code` → Tailwind `--font-display` (`font-display`). Code Pro is a display face, **not** mono.
  - Source: `~/dev/fonts` (`satoshi/`, `code/`). Copy files in; they are committed.
  - **Build emits them twice and that is accepted**: `next/font/local` copies each file to `.next/static/media/<hash>` (what the built CSS references) while `public/fonts/` also serves the originals at `/fonts/…`, which nothing references. ~134 KB of unreferenced assets ship; not a bug, keep `next/font/local` (preload + fallback metrics) rather than a hand-rolled `@font-face`.
- **Client-component barrels break Turbopack builds.** A Server Component importing a Client Component through a barrel `index.ts` that itself lacks `"use client"` fails with `Export X doesn't exist in target module` ("module has no exports at all"). Import the component file directly, or add `"use client"` to the barrel. Components here are flat files, so keep imports direct.
- Biome needs **`css.parser.tailwindDirectives: true`** to parse `@theme`/`@import "tailwindcss"` in `globals.css`, otherwise `biome check` errors on the Tailwind syntax.

- **The drawing persists in `localStorage`** (`src/lib/canvas/persist.ts`; keys `octodance:drawing:v1`, `octodance:palette:v1`). Strokes live in refs, so without this a reload wipes the user's work — and that includes Next's own full reload on HMR, which is exactly how a real drawing was lost. Saved on each commit/undo/clear and on `beforeunload`/`pagehide`, restored on mount; a cleared drawing **removes the key** rather than storing `[]`. On mount the in-memory strokes win when non-empty (a fast refresh can hold a newer drawing than storage) and are written back. Encoding is compact (flattened `[x,y,…]` points, coords rounded, kind tags `"i"`/`"e"`) and decode validates every field. Gotcha: a kind-tag mismatch between encode and decode rejects *every* stroke silently — it presents as "storage is fine but nothing ever restores".

## Components

- Flat files under `src/ui/components/`, one component per file, **no per-component folder** (e.g. `src/ui/components/canvas.tsx`). Import as `@/ui/components/<name>`.
- **Music**: the panel offers 3 bundled CC0 demo tracks (`DEMO_TRACKS` in `canvas.tsx`; files in `public/music/`; provenance in `CREDITS.md`) that load and play in one click via `useAudio().loadUrl()`, plus an upload fallback. The figure is **audio-reactive** (`rig.ts`: bass→sway, mid→bob, high→tilt, beat→snap), so it barely moves with no track loaded.
- `canvas.tsx`: drawing UI + **Edit mode**. Hand-rolled `<canvas>` for live input (no drawing lib) + `react-colorful` `HexColorPicker`; palette swatches (custom removable, `Add` disabled when present); thickness + preview; Draw/Eraser; Undo/Clear driven by a stroke-model history (cap 30). Canvas is DPR-aware, has **no fixed height**, and is sized from `parent.clientWidth/clientHeight` (border must not be included, else it overflows/clips); it's `absolute inset-0` inside the left grid cell so the control column drives the row height and both columns stay equal.
- **Two modes over one stroke model** (`src/lib/canvas/`): *Edit* renders the in-progress stroke through the **same** `renderScene` (it's appended to the render list each move), so the live view *is* the committed view — **releasing a stroke never changes it**. (An earlier live-raster version drew a start dot + per-segment caps, so strokes visibly popped/thinned on release; don't reintroduce a separate live path.) *Play* runs a `requestAnimationFrame` loop that redraws the whole scene each frame with audio-driven motion. Nothing animates while drawing, and drawing is ignored while playing.
  - `strokes.ts` — pure geometry: `Point`/`InkStroke`/`EraseStroke`/`Stroke` (points normalized 0..1, `width` a fraction of `min(w,h)`). No per-stroke motion data.
  - `rig.ts` — the articulation rig. Contacts are found by proximity (≤ `JOIN_EPS_PX` between an endpoint and another stroke's path), then strokes become **bones that rotate about their own contact endpoint**. Two rules keep joints closed: (a) the pivot is the child's *own* point, never the midpoint between the two strokes (a midpoint pivot opens a gap of up to half the contact distance); (b) any pair touching at **≥ 2 points**, or any contact that would **close a loop**, is merged into one rigid `RigGroup` — such strokes physically cannot articulate relative to each other, and if left as separate bones the ignored second hinge tears open. A stroke the joints do not connect is attached by **nearest-distance single linkage (Kruskal) over components**, capped at `LOOSE_EPS_PX`, with `swing 0` so it rides its parent rigidly — each part joins the closest thing it can. Do **not** reintroduce an "anchored" notion such as "attach to the nearest stroke that already reaches a joint": a cluster whose only edge is between its own members (two eye dots 14 px apart touch *each other*) then counts as anchored and is never bridged — measured on a real drawing, the second eye and a yellow dot sat at `parent=null` while the shape swung (roots=2); the same strokes after switching to single linkage gave roots=1. Also: contacts test **endpoints only** (`ends()` is the first/last point), so two overlapping closed loops never join however close their outlines are. **Verify against the user's real strokes, not pixel metrics** — recordings showed the eyes "moving" while a dot was still a detached root; the tree is the only proof. You can get their exact drawing because it persists to `localStorage`: scan the Chrome LevelDB (`~/Library/Application Support/Google/Chrome/Default/Local Storage/leveldb/`), find the `octodance:drawing:v1` key, take the entry with the most strokes, seed it via `agent-browser eval --stdin`, and dump `window.__rig`. `rigMatrices` returns one matrix per group (`time` = seconds since playback started, with a ~0.33 s ease-in ramp so starting a track does not snap). Debug tip: to check the tree, temporarily expose the built rig on `window` and print each stroke's `groupOf`/`parent`/`swing` — the parent/swing numbers prove attachment far better than pixel diffing, because a detached stroke still gets the same whole-figure transform as a root.
  - `render.ts` — `renderScene(ctx, strokes, features, time, w, h, intensity)`; while animating it applies each stroke's **group** matrix (`rig.groupOf[strokeIndex]`) then draws the stroke. Ink strokes are drawn from a per-frame **wiggled** path (`buildWiggledPath`: sub-pixel, time-varying offset tapered to zero at both ends so joints stay welded); erase strokes keep their cached path. Still/editing (`isStill(features)` or intensity 0) uses identity transforms and plain cached paths, so **live == committed** (verified: static frame-to-frame change is exactly 0). Cache key must include canvas size **and point count** (the in-progress stroke grows while drawing), or the live stroke renders stale/truncated.
  - **Motion design constraints (each was a real bug, do not regress):** per-stroke *transforms* (translate/scale) pull joints apart — bones must **rotate about the joint** instead. A single whole-scene rigid transform keeps joints but reads as "the whole thing moving on its own" and is too subtle. A per-point displacement field welds joints but squeezes/stretches the drawing. Pivoting on the midpoint of a contact opens a gap. Feature values after the gamma curve sit near ~0.2, so scale them before multiplying by amplitudes or nothing visibly moves. Per-limb **random** `freq`/`phase`/`dir` makes six limbs jitter on unrelated clocks — derive them from position instead. Applying a beat *instantly* at high amplitude teleports the pose (measured 25° between frames 80 ms apart in a screen recording) and reads as jitter: ease each group's angle toward its target (`RigGroup.angle`) and keep `swing` moderate.
  - **Verifying motion** (there is no test suite): either drive the page with `agent-browser` (measure frame-to-frame pixel change — **not** the ink centroid, which cancels out because limbs rotate in random directions), or measure the user's screen recording: `ffmpeg -vf "crop=W:H:X:Y,fps=30,scale=230:268,format=gray" -f rawvideo -pix_fmt gray` then diff consecutive frames in a small Node script. Two things to check: (a) frame-to-frame change is bursty (p90/median ≈ 2.5–5 = beat-driven, ≈1 = either static or constant wobble), and (b) the ink **connected-component count never exceeds its value when static** — that is the joint-tearing test.
  - `audio.ts` — `useAudio()`: upload (`load(File)`) or bundled demo (`loadUrl(url, name)`) → `decodeAudioData` → source → `AnalyserNode` (smoothing 0.5); `sample()` returns bass/mid/high/level/beat at call time (never React state), consumed by the rAF loop; spectrum bins get a gamma curve so dynamics read. `beat` is an **onset**: a rise in the raw time-domain energy (`getByteTimeDomainData`, which `smoothingTimeConstant` does not affect) above an adaptive baseline, with a 180 ms refractory. **Do not detect it with a level ratio on `bass`** — on a loud sustained track `bass` sits within a hair of its own average, so the ratio never fires (measured: zero beats in 3 s, i.e. the music contributed nothing). Keep the ~40-frame warm-up or every frame at playback start counts as a beat. To check it, measure frame-to-frame **pixel change**, not the ink centroid: limbs rotate in random directions, so centroid motion cancels out and hides the effect (it read as "no correlation" while pixel change showed 4.8× and r = 0.98).
  - Loop/stroke state lives in refs (no per-frame `setState`); resize re-renders from the model, so history survives (unlike the old pixel-copy approach).
